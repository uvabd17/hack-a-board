hack<a>board — capacity planning

How much load the platform handles, when to upgrade, and what each component actually needs. All numbers grounded in a full code audit, not guesses.

tl;dr

Today, free stack is enough. Your one 500-team November event runs comfortably on $0/month.

The moment you book a second concurrent event for the same weekend, upgrade to $26/month (Render Starter $7 + Neon Launch $19). Both are 1-click upgrades, downgradeable any time, zero migration.

6. What can break — ranked by real likelihood

Risk Likelihood What happens What protects you
Venue wifi is bad high Phones disconnect, feels broken Adaptive polling auto-degrades to 20s intervals
Single user hits new bug medium One user errors out Reload page; work around manually for one team
Render shared CPU lags medium Display refresh 1–3s slow 10s Redis leaderboard cache absorbs most of it
Neon hiccup low 1–2s query latency spike Rate limits + cache buffer it
UptimeRobot ping fails 15+ min low Render sleeps, cold start 30s Set 2-min ping interval during events
Full platform outage (Vercel + Neon + Render all down) very low Total outage Not preventable; backup spreadsheet for 20 min

Notice: "platform crashes under expected load" is not on this list. The numbers say you have headroom even at 3-event peak.

7. Pre-event checklist — 15 minutes the day before

  • Hit https://hackaboard.app from a phone on cellular data — loads under 3 seconds
  • Open /h/[slug]/display on the actual projector — leave for 10 min, watch for disconnect badges (should be none)
  • Submit one test score from a judge phone — display updates in ~2 seconds
  • Check UptimeRobot dashboard — socket server at 100% uptime past 7 days
  • Bookmark Vercel deployments page on the venue laptop (rollback is one tap)
